# Intro figure (Figure 1) — spec, v1

Status: **v1 (2026-09-04)**. Data authority: `figure_src.csv` (provenance in
its `#` header, regenerated by `build_figure_src.py`). Generator:
`make_figure.py` (matplotlib, built at final physical size; every aesthetic
value is a **[knob]** in its single `CONFIG` block). Design rationale and
the rejected alternatives: `intro_options.html` (options page, 2026-09-04).

## 1. Purpose and rulings (user, 2026-09-04)

- Shows the **natural imbalance of experts' communication demand** on real
  routing, and its one hardware materialization: the **default static
  contiguous placement with one NIC per GPU**. No placement algorithm, no
  topic-mismatch story — those belong to later sections.
- **One model, two topics.** Model: Kimi K2 (384 experts, top-8). Topics:
  `livecodebench/execution` and `mmlu/professional_law` — the extreme pair
  (hot-set overlap 7%; the mild pair, college math, overlaps 26%)
  **[knob: TOPICS]**.
- **Single-column NSDI**: width 3.33 in **[knob: FIG_W]**; height
  **0.30 × the 9.0 in text height = 2.70 in** **[knob: FIG_H]** ("0.3x
  vertical weight for now").
- Left half **(a)**: **overlapped bar chart**, x = **fixed expert IDs**
  (no sorting in either topic's favor), no tick labels, axis label
  "Expert ID"; y = "Normalized token count" = routed tokens per expert /
  uniform share, dashed line at 1 **[knobs: X_LABEL, Y_LABEL,
  UNIFORM_LINE]**. Two translucent, overlappable colors **[knob:
  BAR_COLORS, BAR_ALPHA]**: deep green `#2f7a4d` (LiveCodeBench) and blue
  `#3d6fb4` (prof. law) at α 0.62 — the overlap reads as a darker teal; both
  are outside the heatmap's hue range and outside the main-perf "Ours" blue.
- Right half **(b)**: **two 16×16 heatmaps stacked top/bottom**, one per
  topic, **shared color scale** [0, max over both] with the 1× tick
  labelled **[knobs: VMIN, VMAX]**. Colormap **magenta → orange**
  (light pink → magenta `#c2185b` → orange `#f57c00`) **[knob:
  CMAP_STOPS]**. Node boundaries as thin black lines (4 ranks per node).
  Rows = sender rank (token home), columns = receiver rank (expert
  owner); ticks at 0/4/8/12.
- Typography: Helvetica/Arial, TrueType embedded (`pdf.fonttype 42`),
  sizes 6–7.5 pt at final size **[knobs: FONT_FAMILY, FS]**.

## 2. Data contract (`figure_src.csv`)

- Source: real routing pools ("Patterns behind Chaos", arXiv 2510.05497)
  read through `sweeps/gen_trace_routing.load_layer_pool` — the same code
  path the sweeps use. **Layer 5, decode slots [64, 96)** (the evaluated
  window of SCHEMA rule 10).
- `kind=expert`: per-expert routed-token count of the whole window pool,
  divided by the uniform share (G experts, top-8) — a pool marginal, not a
  sampled batch.
- `kind=cell`: a batch sampled exactly as the sweeps sample (`sem=homog`,
  T = 2048 tokens per source rank, seed 0), mapped to a [16][16] chunk
  matrix under contiguous ownership (expert e → rank e // 24), divided by
  the mean cell. Diagonal kept (real tokens route home).
- Regenerate: `python3 build_figure_src.py` (stdlib; needs `$PSCRATCH`
  trace pools). Render: conda `andrewy-comet` python,
  `python3 make_figure.py`.

## 3. Known readings to keep honest

- Under equal per-rank batches the heatmaps are **column-striped**: every
  sender has the same profile (row sums are exactly T × top-k), so the
  imbalance is receiver-side. Say so in the caption: no GPU sends more,
  one NIC receives more; and the hot column moves with the topic
  (rank 4 at 1.57× on LiveCodeBench, rank 3 at 2.21× on prof. law).
- The prof.-law hottest expert is 33× uniform vs 9.5× on LiveCodeBench; a
  full-range y axis squashes the LiveCodeBench profile. `Y_MAX` clips and
  annotates the clipped bars if the compressed look loses.
